Dokandar Inventory - Complete Documentation

Comprehensive guide from Flutter setup to Play Store deployment. This inventory management app tracks products, sales, customers, and provides backup/restore features.

  • Version: 1.0.1
  • Framework: Flutter 3.5.4 / Dart 3.x
  • State Management: GetX 4.7.2
  • Languages: English & Bengali
  • Database: Isar 3.1.0 (local NoSQL)
  • Min Android: API 21 (Android 5.0)

Quick Path: Already have Flutter? Jump to Project Setup. Complete beginner? Start with Flutter Installation.

Key Features

  • Product inventory management with categories
  • Sales tracking with invoice generation (PDF)
  • Customer management with due payment tracking
  • Store setup and configuration
  • Local database backup/restore (JSON)
  • Multi-language support (Bengali/English)
  • Light & Dark theme
  • Subscription plans (configurable)

System Requirements

Operating System

  • Windows: Windows 10 or later (64-bit), x86-64 based
  • macOS: macOS 10.15 (Catalina) or later
  • Linux: Ubuntu 18.04 or later (64-bit)

Software Requirements

  • Flutter SDK 3.5.4 or higher
  • Dart SDK 3.x (comes with Flutter)
  • Android Studio 2022.3 or VS Code 1.80+
  • JDK 17 (OpenJDK or Oracle JDK)
  • Android SDK (API 21 to 35)
  • Git for version control

Hardware Requirements

  • Disk space: 5 GB minimum (10 GB recommended for Android SDK)
  • RAM: 8 GB minimum (16 GB recommended)
  • Processor: Intel i3 / AMD Ryzen 3 or better

For Publishing

  • Google Play Console account ($25 one-time fee)
  • Valid payment method for registration
  • Privacy policy URL (required for Play Store)

Flutter SDK Installation

Follow the instructions for your operating system below.

Windows Installation

  1. Download Flutter: Visit flutter.dev and download the Flutter SDK ZIP file (latest stable channel).
  2. Extract: Extract the ZIP to C:\src\flutter (avoid spaces or special characters in path).
  3. Add to PATH:
    • Open Control Panel → System → Advanced system settings → Environment Variables
    • Under User variables, find Path, click Edit
    • Click New and add: C:\src\flutter\bin
    • Click OK to save
  4. Verify: Open a new Command Prompt and run: 
    flutter --version
flutter doctor
  5. Install Git: Download from git-scm.com and install with default settings.

macOS Installation

  1. Download Flutter: Get the ZIP from flutter.dev.
  2. Extract: Unzip to your home directory: 
    cd ~
unzip ~/Downloads/flutter_macos_*.zip
  3. Add to PATH: Open terminal and run: 
    export PATH="$PATH:$HOME/flutter/bin"
# Make it permanent (for zsh shell):
echo 'export PATH="$PATH:$HOME/flutter/bin"' >> ~/.zshrc
source ~/.zshrc
  4. Verify: 
    flutter --version
flutter doctor
  5. Install Xcode Command Line Tools: 
    xcode-select --install

Linux Installation

  1. Download Flutter: Get from flutter.dev.
  2. Extract: 
    cd ~
tar xf ~/Downloads/flutter_linux_*.tar.xz
  3. Add to PATH: 
    export PATH="$PATH:$HOME/flutter/bin"
# Add permanently to ~/.bashrc:

source ~/.bashrc

App Architecture

This app follows MVC (Model-View-Controller) pattern with GetX framework.

Architecture Flow

  1. Entry Point (main.dart):
    • Initializes Flutter bindings
    • Starts DatabaseService (Isar)
    • Loads AppConfig & AppThemeConfig
    • Starts LocalizationService (if multi-language enabled)
    • Initializes global controllers (Navigation, Settings, Home, Sell, Inventory)
    • Checks if user exists → routes to MAIN or SETUP
  2. Routing (app_pages.dart): GetX page routes with bindings
  3. State Management: GetX reactive programming (Obx, Rx variables)
  4. Database: Isar (NoSQL, local-first, embedded)
  5. UI Flow: Setup → Main (with bottom nav) → Home/Inventory/Sell/Settings

Key Patterns Used

  • Dependency Injection: GetX Bindings inject controllers into views
  • Reactive State: .obs variables with Obx() widgets
  • Repository Pattern: DatabaseService abstracts Isar operations
  • Service Locator: Get.find<Service>() retrieves singletons
// Example: How a view talks to database
// 1) Controller fetches data
class HomeController extends GetxController {
  final dbService = Get.find<DatabaseService>();
  final products = <Product>[].obs;  // Reactive list
  
  @override
  void onInit() {
    super.onInit();
    loadProducts();
  }
  
  Future<void> loadProducts() async {
    products.value = await dbService.getAllProducts();
  }
}

// 2) View observes controller
class HomeView extends GetView<HomeController> {
  @override
  Widget build(BuildContext context) {
    return Obx(() => ListView.builder(
      itemCount: controller.products.length,
      itemBuilder: (context, index) => ProductTile(controller.products[index]),
    ));
  }
}

Localization (Multi-Language)

App supports Bengali (বাংলা) and English. Users can switch in Settings.

Files Involved

  • lib/app/core/services/localization_service.dart – Language switching logic
  • lib/l10n/app_localizations.dart – Generated localization delegate
  • lib/l10n/app_en.arb – English strings
  • lib/l10n/app_bn.arb – Bengali strings

How It Works

// 1) LocalizationService stores selected language in SharedPreferences
class LocalizationService extends GetxService {
  final Rx<Locale> currentLocale = const Locale('bn', '').obs;
  
  Future<bool> changeLanguage(String languageCode) async {
    await _prefs.setString('app_language', languageCode);
    final newLocale = Locale(languageCode, '');
    currentLocale.value = newLocale;
    Get.updateLocale(newLocale);  // Updates entire app
    return true;
  }
}

// 2) In main.dart, set supported locales:
supportedLocales: const [
  Locale('bn', ''),  // Bengali
  Locale('en', ''),  // English
],

Change Default Language

Edit lib/app/config/app_config.dart:

static const String defaultLanguage = 'en';  // Change 'bn' to 'en'

Add More Languages

  1. Update AppConfig.availableLanguages: 
    static const Map<String, String> availableLanguages = {
  'bn': 'বাংলা',
  'en': 'English',
  'hi': 'हिन्दी',  // Add Hindi
};
  2. Create lib/l10n/app_hi.arb with translated strings
  3. Add Locale('hi', '') to supportedLocales in main.dart
  4. Run flutter pub get to regenerate

User Changes Language

Settings → Language → Select from list → App rebuilds with new strings

App Signing (for Release)

Critical: You MUST sign your app before uploading to Play Store. Never share your keystore file!

Step 1: Create Keystore

Open terminal in project root:

# Windows:
keytool -genkey -v -keystore C:\Users\YourName\upload-keystore.jks -storetype JKS -keyalg RSA -keysize 2048 -validity 10000 -alias upload

# Mac/Linux:
keytool -genkey -v -keystore ~/upload-keystore.jks -storetype JKS -keyalg RSA -keysize 2048 -validity 10000 -alias upload

You'll be asked:

  • Keystore password (choose strong, save it!)
  • Your name, organization, city, state, country
  • Key password (can be same as keystore password)

⚠️ Backup your keystore & passwords! If lost, you can NEVER update your app on Play Store.

Step 2: Create key.properties

Create file android/key.properties (this file is in .gitignore, won't be committed)

storePassword=your_keystore_password
keyPassword=your_key_password
keyAlias=upload
storeFile=C:/Users/YourName/upload-keystore.jks
# For Mac/Linux: storeFile=/Users/yourname/upload-keystore.jks

Step 3: Configure build.gradle

Edit android/app/build.gradle, add BEFORE android { block:

// Add this near top, after plugins:
def keystoreProperties = new Properties()
def keystorePropertiesFile = rootProject.file('key.properties')
if (keystorePropertiesFile.exists()) {
    keystoreProperties.load(new FileInputStream(keystorePropertiesFile))
}

android {
    // ... existing config ...
    
    // Add this INSIDE android block, BEFORE buildTypes:
    signingConfigs {
        release {
            keyAlias keystoreProperties['keyAlias']
            keyPassword keystoreProperties['keyPassword']
            storeFile keystoreProperties['storeFile'] ? file(keystoreProperties['storeFile']) : null
            storePassword keystoreProperties['storePassword']
        }
    }
    
    buildTypes {
        release {
            signingConfig signingConfigs.release  // Add this line
        }
    }
}

Step 4: Verify

flutter build apk --release
# Should succeed without keystore errors

Backup & Restore

File: lib/app/core/services/backup_service.dart (385 lines)

How It Works

  1. Export: All Isar collections → JSON file
  2. Saved to: /storage/emulated/0/Dokandar/Backup/
  3. Filename: backup_DD-MM-YYYY_HH-MM-SS.json
  4. Import: JSON → Clear DB → Insert all records

Export Code

// lib/app/core/services/backup_service.dart (excerpt)
Future<String> exportIsarToFile() async {
  // 1) Fetch all data
  final sales = await isar.sales.where().findAll();
  final products = await isar.products.where().findAll();
  final customers = await isar.customers.where().findAll();
  // ... more collections
  
  // 2) Convert to JSON
  final backupData = {
    'sales': sales.map((s) => {...}).toList(),
    'products': products.map((p) => {...}).toList(),
    // ...
  };
  
  // 3) Write to file
  final timestamp = DateFormat('dd-MM-yyyy_hh-mm-ss a').format(DateTime.now());
  final backupFile = File(path.join(_backupDir.path, 'backup_$timestamp.json'));
  await backupFile.writeAsString(jsonEncode(backupData));
  
  return backupFile.path;
}

Frequently Asked Questions

Do I need to know Flutter/Dart to customize this app?
For basic customization (app name, colors, currency, features on/off), just edit app_config.dart—no coding needed. For deeper changes (UI layout, new features), Flutter knowledge helps but the code is well-organized and commented.
Can I use this app offline?
Yes! The app uses local Isar database—no internet required. All data is stored on the device. (If you want cloud sync, you'd need to integrate a backend, which isn't included.)
How do I change the app name and icon?
Name: Edit appName in lib/app/config/app_config.dart and android:label in AndroidManifest.xml.
Icon: Add your 1024x1024 PNG to assets/icon.png, configure flutter_launcher_icons in pubspec.yaml, run flutter pub run flutter_launcher_icons. See Icons section.
How to change the package ID (com.example.app)?
Edit applicationId and namespace in android/app/build.gradle, update package in AndroidManifest.xml, and optionally rename folder structure + MainActivity.kt package. See Change App ID section.
Can I disable subscription features?
Yes. Set enableSubscription = false; in app_config.dart, then rebuild. The subscription UI will be hidden.
How do I reset all data?
Create a backup first (Settings → Backup Data). Then clear app data from device Settings → Apps → Dokandar → Storage → Clear data. Reopen the app and restore backup if needed.
Where is the database file stored?
/data/data/com.nexcode.studio.dokandar_app_inventory/files/default.isar (inaccessible without root). Users can't access it directly—use the in-app Backup feature to export data.
Can I add more languages?
Yes. Add language to AppConfig.availableLanguages, create lib/l10n/app_XX.arb with translations, add Locale('XX', '') to main.dart supported locales, run flutter pub get. See Localization section.
App crashes on launch?
Run flutter clean, flutter pub get, rebuild. Check terminal for error logs. Common causes: missing dependencies, corrupted build cache, incompatible Flutter version. See Troubleshooting.
Can I sell this app to my clients?
Check your CodeCanyon license. Regular License = one end product for one client. Extended License = multiple end products or SaaS. You cannot resell the source code as-is on CodeCanyon or other marketplaces.
